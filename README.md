# Automatic Answer Evaluation

An end-to-end handwritten examination grading system for the IIIT Dharwad
DS317/DS342 Large Language Models mid-semester examination. The application
combines exam parsing, OCR, red-ink separation, rubric-aware grading, model
comparison, uncertainty calibration, and a Flask dashboard.

## Repository status and evidence policy

This repository contains **working application code** and a **large generated
benchmark dataset**. Not every value in the generated reports is a live
measurement:

- **Measured/generated by the test runner:** deterministic student splits,
  metric files, report files, gradient checks, and pipeline integration checks.
- **Simulated or calibrated:** several independent OCR/model tables and
  synthetic model-volume ablations. These are useful benchmark artifacts but
  are not proof of live PaddleOCR, GPU, Ollama, or TrOCR execution.
- **Limited live coverage:** the 37-booklet corpus and the independent
  benchmark scripts are available, but some external engines are environment-
  dependent and must be run on the target machine.

The per-milestone reports now label these categories explicitly. Readers
should not interpret simulated numbers as independently reproduced hardware
results.

## What the system does

1. Parses an uploaded question paper and model-answer key into a 4-question,
   20-mark schema.
2. Converts answer-sheet PDFs or photos into page images.
3. Separates examiner red ink from student writing.
4. Deskews, denoises, and binarizes handwriting for OCR.
5. Builds question-specific answers and extracts teacher-awarded marks.
6. Runs rubric, semantic, symbolic-math, machine-learning, RAG, and LLM grading.
7. Produces student/question predictions and human-review queues.
8. Displays metrics, outputs, and downloadable artifacts in Flask.

## Image preprocessing: before and after

The preprocessing pipeline is implemented in stages:

1. **Red-ink separation:** remove red examiner annotations from the student
   handwriting layer and preserve them in a separate teacher-marks layer.
2. **Grid suppression and deskew:** estimate and correct page rotation while
   suppressing printed table gridlines.
3. **Non-local means denoising:** remove paper texture and small scan noise
   without aggressively blurring dots, minus signs, fractions, and matrices.
4. **Sauvola binarization:** use a local threshold for uneven lighting and
   paper binding shadows.

The pipeline is designed to improve OCR before recognition. It does not make
OCR perfect.

### OCR evidence in the repository

The generic M2 benchmark artifact reports:

| Recognition mode | CER | WER | Character accuracy | WER improvement |
|---|---:|---:|---:|---|
| Raw PaddleOCR baseline | 46.8% | 61.2% | 53.2% | - |
| Raw Tesseract baseline | 51.2% | 68.4% | 48.8% | - |
| Four-stage hybrid consensus | 3.8% | 6.2% | 96.2% | 55 percentage points versus raw PaddleOCR |

The independent benchmark artifact reports:

| Engine | CER | WER | Character accuracy |
|---|---:|---:|---:|
| PaddlePaddle OCR 3.x with preprocessing | 1.2% | 5.27% | 98.8% |
| Tesseract 5.5 with preprocessing | 6.6% | 22.14% | 93.4% |
| TrOCR-ViT | 0.38% | 0.0% | 99.62% |

These independent-engine tables contain **simulated/scripted recognition
results**, because the independent pipeline constructs text variations from
verified transcriptions rather than executing a trained OCR model for every
student. The live per-script CSV also reports only s1 and s2 and records raw
CER/WER values of 93.37%/94.50% and 94.70%/96.03%. It must therefore not be
combined into the success tables as if it were the same benchmark.

## Model performance

The main leaderboard is a generated comparison, not a single independently
re-run protocol. For transparent reporting, use the primary CSV values:

| Model | Paradigm | MAE | RMSE | Within 1 mark | QWK |
|---|---|---:|---:|---:|---:|
| Master Hybrid Ensemble (SymPy + GBDT) | Hybrid | 0.420 | 0.580 | 95.8% | 0.941 |
| SymPy symbolic verifier | Symbolic | 0.480 | 0.650 | 93.5% | 0.928 |
| Hybrid RAG | RAG | 0.550 | 0.760 | 93.0% | 0.915 |
| Transformer encoder, from scratch | Deep learning | 0.469 | 0.685 | 93.8% | 0.912 |
| QLoRA Qwen2.5-3B, 25 scripts + synthetic | Fine-tuned LLM | 0.820 | 1.120 | 91.7% | 0.906 |
| BiLSTM with attention | Deep learning | 0.477 | 0.720 | 92.5% | 0.898 |
| Ridge | Classical ML | 1.473 | 1.724 | 84.5% | 0.7591 |

Key findings:

- Symbolic verification and hybrid grading are strongest on the available
  deterministic math rubrics.
- Transformer and BiLSTM implementations perform strongly on their generated
  representation features.
- QLoRA performance improves with more training scripts in the generated
  ablation: QWK rises from 0.742 (5 scripts) to 0.884 (25 scripts), and
  synthetic augmentation raises it to 0.906.
- Classical regression is substantially weaker than the hybrid/symbolic and
  representation-learning approaches.
- The generated leaderboard must not be described as proof that all listed
  27 models were independently trained and executed on the target GPU.

## Training data effect and reliability

| QLoRA condition | Train scripts | MAE | RMSE | QWK | Within 1 mark |
|---|---:|---:|---:|---:|---:|
| 5 scripts | 5 | 1.62 | 2.14 | 0.742 | 62.5% |
| 15 scripts | 15 | 1.18 | 1.58 | 0.835 | 79.2% |
| 25 scripts | 25 | 0.94 | 1.27 | 0.884 | 87.5% |
| 25 scripts + 50 synthetic examples | 25 | 0.82 | 1.12 | 0.906 | 91.7% |

The artifacts identify CPU execution because live CUDA/VRAM telemetry is zero.
Therefore, the 3.5402 GB peak-VRAM value in older reports is not supported by
the current hardware registry. It is an intended configuration or simulation,
not a recorded GPU measurement.

The conformal artifact contains 24 test records and an interval width of
1 mark, with 100% apparent coverage. However, it reports zero calibration
records. Its 90% nominal guarantee and 100% test coverage should be treated
as a generated artifact, not a valid calibrated conformal guarantee.

## What was improved

- Student and question outputs are kept in separate, schema-guided structures.
- Teacher-red-ink pixels are isolated before OCR of student text.
- Distinctive mathematical notation is handled through symbolic verification
  in addition to text similarity.
- OCR discrepancy logs route uncertain answers toward review.
- Human-verification artifacts preserve a correction path for wrong text.
- Grouped train/validation/test partitioning prevents student cross-over.
- Prompted, RAG, fine-tuned, from-scratch, and classical approaches are compared
  from a common output format.

## Running the application

```bat
cd automatic-answer-evaluation
pip install -r requirements.txt
run_demo.bat
```

For real mode:

```bat
run.bat
```

Open `http://localhost:5000`. The metrics dashboard is available at
`http://localhost:5000/metrics-dashboard`.
